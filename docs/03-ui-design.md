# 03. 화면 설계

## 시안 비교
| 시안 | 특징 | 어울리는 상황 |
|---|---|---|
| A+B 메신저+뷰어 | 말풍선 대화, 출처 칩, 모바일 하단 시트 | 핸드폰에서 자주 물어볼 때 |
| C 검색형 | 큰 검색창, 요약 답변+출처 카드, 후속 질문 칩 | 특정 문구를 빠르게 찾을 때 |
| D 3단 작업공간 | 문서 목록 / 대화 / 원문, 어두운 배경 | 노트북에서 문서를 대조할 때 |

## 최종 결정: A+B+D 통합
- 대화는 **말풍선(A+B)** 형태.
- 출처 버튼은 **D 방식**: 호박색 테두리 버튼(`약관 p.143`)을 누르면 눌린 상태로 채워지고 원문이 바뀐다.
- **원문은 새 창·시트 없이 답변 바로 아래에 펼친다.** 같은 버튼을 다시 누르면 접힌다. 근거 문장은 형광펜 표시.
- PC는 왼쪽 문서·버전 목록 + 대화의 2단. 목록에서 이전 버전(v2, v1)을 누르면 해당 버전 표시로 원문이 열린다.
- 상단에 **기준 버전 선택**(최신 / 특정 날짜 버전)과 **흑/백 테마 전환**. 테마는 기기 설정을 따르되 선택을 기억한다.

## 답변과 근거의 위계 (증빙 원칙)
- 답변 본문은 모델이 쓴 **요약**이라 틀릴 수 있다. 서버가 원문과 대조해 확인한 것은 **인용문**뿐이다.
- 그래서 화면은 인용문(형광펜 원문)을 근거의 기준으로 강조하고, 답변 아래에 안내 문구를 항상 붙인다:
  "답변은 요약이에요. 근거는 아래 인용문을 기준으로 확인해 주세요."
- 확인된 인용이 하나도 없으면 답변을 근거 있는 답처럼 보이지 않게 표시한다(예: 흐린 색 + "확인된 원문 인용이 없어요").

## 접속 화면
로그인 / 가입 / 이메일 인증 / 승인 대기 / 관리자 승인 / 비밀번호 찾기(코드 → 새 비밀번호 → 완료). 흐름은 `04-auth-flow.md` 참고.
- 입력 오류는 필드 바로 아래에 고칠 방법을 안내한다.
- 비밀번호 찾기 안내문은 "가입된 이메일이라면 코드를 보냈어요"로 써서 가입 여부를 드러내지 않는다.

## 홈 화면 앱 (PWA, 2026-10-05)
- 스토어 앱 대신 **홈 화면에 추가하는 웹앱**. 아이폰·안드로이드 모두 무료, 업데이트는 서버 파일만 바꾸면 바로 반영.
- 아이콘: 어두운 바탕 + 문서 한 장 + 근거 문장 형광펜 (`server\static\icons\icon.svg`, PNG는 `make_icons.py`로 생성. 안드로이드용 여백 있는 maskable 포함)
- `manifest.json`: 이름 "문서 도우미", 주소창 없는 전체 화면(standalone), 세로 화면, 바탕·상단 색 #151A26
- `sw.js`(서비스 워커): 화면 파일은 항상 서버에서 새로 받고 못 받을 때만 저장본 사용. **/api(질문·답변·원문)는 절대 저장하지 않음**(증빙: 항상 서버의 최신 원문). 서버에 닿지 못하면 "서버에 연결할 수 없어요" 안내
- 설치: 계정 메뉴 "📲 앱으로 설치". 안드로이드 크롬·PC 크롬/엣지는 설치 창, 아이폰은 "Safari 공유(□↑) → 홈 화면에 추가" 안내. 이미 앱으로 열었으면 숨김
- 확인: 아이콘·manifest 응답, sw.js 문법(Edge). 실제 설치는 핸드폰에서 확인 필요(앱 안 브라우저 패널은 서비스 워커를 지원하지 않음)

## 문구 원칙
- 해요체, 능동형, 버튼은 하는 일을 그대로 쓴다 ("승인 요청 보내기", "비밀번호 변경").
- 화면 속 약관 문구는 확인용 샘플이며 실제 내용이 아니다.
